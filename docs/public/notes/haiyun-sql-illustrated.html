Q1

换柜数据精准统计

★★☆☆☆
数据清洗 + 口径修正 · 货物换柜后旧柜数据残留，导致按柜统计失真
数据清洗换柜迁移LEFT JOIN 补0ROW_NUMBER 取最新
①口径 7月入库 / 有效 / 剔退仓 / 最新柜号归属 / 补0 ②关系 主表=柜清单 ③CTE 映射→过滤→迁移 ④组装 LEFT JOIN + GROUP BY
CTE1 container_map · 换柜映射框
SELECT cargo_no, new_container_no AS latest_no, ROW_NUMBER() OVER(PARTITION BY cargo_no ORDER BY change_time DESC) AS rn FROM dwd_sea_container_change
→ 每票货按换柜时间倒序编号，rn=1 就是最新柜号
CTE2 valid_inbound · 有效入库框
SELECT * FROM dwd_sea_goods_inbound_full WHERE data_status='有效' AND inbound_type<>'退仓' AND inbound_time >= '2026-07-01' AND inbound_time < '2026-08-01'
→ Q1 剔退仓负数；Q2 保留（口径不同，最易被追问）
CTE3 migrated · 换柜迁移框
SELECT COALESCE(m.latest_no, i.container_no) AS final_container, i.cargo_no, i.actual_weight, i.actual_volume FROM valid_inbound i LEFT JOIN container_map m ON i.cargo_no=m.cargo_no AND m.rn=1
→ 换过柜：历史记录挂到最新柜号；没换过：保持原样
最终 SELECT · 主表 JOIN + 聚合框
SELECT b.container_no, COALESCE(SUM(g.actual_weight),0) AS final_total_weight, COALESCE(SUM(g.actual_volume),0) AS final_total_volume, COUNT(DISTINCT g.cargo_no) AS cargo_ticket_cnt FROM 柜清单 b LEFT JOIN migrated g ON b.container_no=g.final_container WHERE b.dt='2026-07-31' AND b.del_flag=0 GROUP BY b.container_no
→ 主表必须是柜清单（空柜才在结果里）；SUM 碰 NULL 用 COALESCE 补 0
⚠ 追问点：表2 的 container_no 若被业务库「回刷」成最新柜号，CTE1/CTE3 都不用写——写码前先和业务确认口径。
举一反三：

把需求改成「统计每个客户的总重量体积」——只需把最终 SELECT 的 GROUP BY 和输出从 container_no 换成 cust_id，主表换表1 的客户维度即可。试试自己改。

Q2

海运进仓异常数据统计

★★★☆☆
异常指标计算 · 四类异常柜 → 客户级风控复盘
条件聚合COUNT(IF)异常监控多口径
①口径 7月计划开船 / 有效 / 退仓保留 ②关系 柜全集 LEFT JOIN 柜级事实 ③CTE 柜级聚合打标 ④组装 GROUP BY cust_id
核心骨架
-- CTE3 柜级聚合：一次算出四个判定条件 SELECT container_no, SUM(actual_weight) AS total_w, -- 全额退仓判定 COUNT(1) AS inbound_cnt, -- 空柜判定 MIN(inbound_time) AS first_time -- 延期判定 FROM valid_inbound GROUP BY container_no; -- ④ 柜级打标 → 客户级汇总 SELECT v.cust_id, COUNT(1) AS total_container_cnt, COUNT(IF(c.total_w > v.book_weight,1,NULL)) AS over_weight_cnt, COUNT(IF(c.total_w = 0,1,NULL)) AS full_refund_cnt, COUNT(IF(c.inbound_cnt IS NULL,1,NULL)) AS empty_cnt, COUNT(IF(c.first_time > CONCAT(STRING(v.old_plan_sail_date),' 23:59:59'),1,NULL)) AS delay_inbound_cnt, ROUND((超量+退仓+空柜+延期)/COUNT(1), 2) AS abnormal_ratio FROM valid_container v LEFT JOIN container_stat c ON v.container_no=c.container_no GROUP BY v.cust_id;
→ 空柜来自「柜全集 LEFT JOIN 无匹配」；COUNT(IF(…,1,NULL)) = 条件计数
⚠ 两个坑：① 退仓记录必须保留（全额退仓=累计为 0，和 Q1 剔除口径相反）；② 一个柜可同时命中多类异常，占比分子是「异常人次」，业务要「去重柜数」就用 MAX(IF(…,1,0)) 先柜级去重。
举一反三：

把「超量」判定改成「体积超量」——只需把比较字段换成 book_volume / SUM(actual_volume)，其余骨架不动。

Q3

月度进仓时效分层排名

★★★☆☆
时间窗口 + 高阶窗口函数 · 耗时按小时 · 港口内周排名
窗口函数DENSE_RANK时间计算分组排名
①口径 完结状态3种 / 耗时=末次入库-创建(小时) ②关系 完结柜 JOIN 末次入库 ③CTE 归周→算耗时 ④组装 DENSE_RANK
核心骨架
-- CTE3 耗时（小时，非天） ROUND((UNIX_TIMESTAMP(l.last_time) - UNIX_TIMESTAMP(f.create_time))/3600, 1) AS inbound_hours -- ④ 归周 + 排名 CONCAT('2026-W', LPAD(WEEKOFYEAR(plan_sail_date),2,'0')) AS stat_week SELECT stat_week, dest_port, container_no, inbound_hours, DENSE_RANK() OVER(PARTITION BY dest_port, stat_week ORDER BY inbound_hours ASC) AS port_week_rank FROM inbound_hours;
→ 题目「区分并列排名」→ 用 DENSE_RANK

窗口函数三兄弟（必考）

⚠ 追问点：周按哪个日期归？跨周进仓的柜算哪周？题目没定义——先声明口径假设，体现生产意识。
举一反三：

把「耗时升序」改成「耗时降序取前3」——把 DENSE_RANK 换成 ROW_NUMBER，ORDER BY 改 DESC，外层 WHERE rn <= 3。

Q4

快照数据修正统计

★★★★☆
数据回溯 + 分区快照 · 用 7-31 最终状态修正整月历史
分区快照口径回溯自连接完成率
①口径 每日存在性 + 最终状态修正 ②关系 每日快照 JOIN 最新快照 ③CTE 修正→按日聚合 ④组装 完成率防除零
核心骨架
-- 每日快照 × 最新快照：剔除"后来被删"的历史数据 SELECT d.dt, d.container_no, d.container_status FROM dwd_sea_booking_full d JOIN latest_snapshot l ON d.booking_id=l.booking_id AND d.container_no=l.container_no WHERE d.dt >= '2026-07-01' AND d.dt < '2026-08-01' AND d.del_flag=0 -- 当日快照正常 AND l.del_flag=0 -- 最终也没被删（口径回溯核心） -- 完成率：GREATEST 防除零 ROUND(finish / GREATEST(total,1) * 100, 2) AS daily_complete_rate
→ 一句话：历史快照只取「存在性」，状态一律以最新快照为准
⚠ 追问点：如果源端物理删除（快照里没有已删记录），历史还原不出来。方案：全量同步带 del_flag 落仓，或改用拉链表（正好接思考题4）。
举一反三：

把「完成率」改成「退单率」——把分子从完结柜数换成 l.del_flag=1 的柜数即可，主表 JOIN 逻辑不变。

Q5

客户拼柜质量综合评分

★★★★★
复杂聚合 + 数据倾斜优化 · Q3 全季度 · 综合得分可上线
数据倾斜两阶段聚合加盐评分建模
①口径 Q3三个月 / 拼柜≥2票 / 合规≤5票 ②关系 柜级→客户级两层聚合 ③CTE 柜事实→客户指标 ④组装 评分公式 + 倾斜三板斧
评分 + 加盐代码
-- 综合得分（在客户级指标上） ROUND((1-empty_cnt/total_cnt)*40 + (1-over_cnt/GREATEST(has_inbound_cnt,1))*30 + compliance_cnt/total_cnt*30, 2) AS score -- 加盐：超热门柜 join 打散，两遍聚合 -- 第一遍：key 加盐打散 CONCAT(container_no, '_', CAST(FLOOR(RAND()*10) AS INT)) AS salted_key GROUP BY salted_key, ... -- 第二遍：去盐后再聚 GROUP BY SPLIT(salted_key,'_')[0]
→ 顺序：先收敛（柜级聚合天然抗倾斜）→ 再加盐 → 小表广播 MAPJOIN
⚠ 追问点：为什么「先柜级再客户级」就是倾斜优化？——热点客户的大表明细先在柜级收敛成小结果，大 JOIN 变小 JOIN。
举一反三：

把「拼柜定义」从票数≥2 改成 ≥3——只需改 SUM(IF(ticket_cnt>=2,1,0)) 里的阈值，评分权重不变。

四道思考题 · 口述要点

1. 换柜场景增量还是全量？
DWD 事实层用「增量流水 + 全量快照」双轨；换柜是缓慢变化维，用 change_time 起止时间重放任意时刻状态，回溯 = change_time ≤ T < 下次变更，不回刷历史。
2. 大表倾斜除加盐外？
① 业务层裁剪：join 前先过滤分区/无效状态；② 分层预聚合：大表先按 key 收敛到 DWS 再 join；③ 小表广播 MapJoin；④ 按热点 key 拆桶隔离。
3. 重跑不一致 3 原因？
① 源端回刷/迟到数据；② 快照覆盖导致口径漂移；③ 依赖时序——上游未就绪读到半截数据。修复：幂等写入 + 就绪校验 + 固定快照口径。
4. 客户宽表拉链表？
(cust_id, 属性…, start_date, end_date)；每日增量比对，变化则闭链(end=昨天)+开新链(start=今天)；查任意历史日 WHERE start_date ≤ T AND end_date > T。
